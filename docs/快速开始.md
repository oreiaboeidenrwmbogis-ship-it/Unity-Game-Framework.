## 一、这是什么

一个 **Unity 2022.3 LTS（C# 9）的游戏项目底座**：把每个游戏都要重写一遍的东西（启动流程、事件总线、UI 栈、输入、音频、设置、配置表、存档、资源加载、对象池、调试面板）做成**类型无关、可运行的模块**，让你从第一分钟就能写玩法。

三条它和"随手写一个 Unity 工程"的区别：

| | |
|---|---|
| **服务化 + 单一启动器** | 所有系统都是**不继承 MonoBehaviour** 的纯 C# 服务，由唯一的 `Bootstrap` 统一 `Init / Tick / Dispose`。场景里没有满天飞的 `Update()` 和 `GetInstance()` 单例 |
| **模块边界是程序集** | 一个模块 = 一个 asmdef = 一个命名空间，依赖严格单向；模块间只通过**强类型事件总线**和接口通信。所以每个模块都能被单独替换或整体删掉 |
| **规矩是写进代码的** | 八条铁律 + 约 107 条测试 + 一个 F1 运行期调试面板；`Resources.Load` 禁用、日志走门面、异步统一 UniTask |

**已完成**：核心循环（事件/时间/池/状态机/场景流转）· UI 面板栈 · 输入 · 音频 · 设置 · 配置表（CSV → 强类型代码 → SO 资产）· 存档（多槽位 + 迁移 + 降级）· Addressables 资源服务 · 对象池 · 日志系统 · 调试面板 · 相机（Cinemachine 薄封装）· 特效池化 · 测试骨架。

**没做**（留给你，模板不预写玩法）：背包 / 任务 / 对话 / 成就 / 本地化，以及 CI、一键出包管线、MessagePack 存档实现。

## 二、60 秒跑起来

1. **克隆并打开**
   ```bash
   git clone https://github.com/oreiaboeidenrwmbogis-ship-it/Unity-Game-Framework.git && cd Unity-Game-Framework
   ```
   用 **Unity 2022.3 LTS**（任意补丁版本；`ProjectSettings/ProjectVersion.txt` 会告诉你是哪一个）。首次导入要几分钟。

2. **必做一次的环境设置**
   `Project Settings → Player → Other Settings → **Active Input Handling = Both**`
   （New Input System 的要求；改完编辑器会重启，不设会在运行时抛错）

3. **打开 `Assets/_Project/Scenes/SampleScene.unity` → Play**

   Console 应依次出现（大致）：
   ```
   [Bootstrap] 核心框架就绪：已注册 14 项服务 [TimeService, GameStateService, ...]
   [UI]   UI 框架就绪（三层：Screen/Popup/Overlay，常驻根）
   [Input] 输入系统就绪：内置 UI 映射 8 个动作，EventSystem 已托管
   [Audio] / [Settings] / [Config] / [Save] / [Assets] / [Vfx] / [Camera] / [Diagnostics] 各自的就绪日志
   ```
   随后**演示时间线**把每个模块演一遍（状态机 Boot→Splash→MainMenu→Loading→Gameplay→Paused、对象池、事件总线、
   配置表、存档、资源、相机、特效、音频、UI 面板栈、设置界面、F1 面板），Console 有编号日志 —— 它同时就是各阶段的验收脚本。

   > 开始写自己的游戏时**把它关掉**：`Gameplay/Demo/DemoRunner.cs` 里 `DemoEnabled` 改成 `false`（一行），
   > 或整个 `Gameplay/Demo` 目录删掉（没有任何模块反向依赖它）。演示是编辑器专用程序集，无论开关如何都不进正式包。

4. **Play 中按 `F1`**（或 `` ` ``）打开**调试面板**：FPS / 内存 / 各服务状态 / 事件监听数 / 对象池 / 资源账本 / 配置表 / 存档槽位，还有命令控制台。第一次用建议把面板自带的"用法说明"页读完。

5. **跑一次测试**
   `Window → General → Test Runner → **EditMode → Run All**`（105 条，秒级）；PlayMode 另有 2 条冒烟测试（会真的进入播放模式，属正常）。
   全绿 = 底座没坏 —— 这是你之后每次改动前的基线。

## 四、架构一页纸

```
        ┌─────────────────────── Bootstrap（唯一的常驻 MonoBehaviour）───────────────────────┐
        │  Play 前自举（BeforeSceneLoad）→ 注册全部服务 → 逐个 Init → 锁定容器               │
        │  每帧 Update 统一驱动 ITickable；退出时逆序 Dispose                                  │
        └──────────────────────────────────────────────────────────────────────────────────┘
                     │ 注册/取用                                ▲ 事件（强类型 struct）
                     ▼                                         │
        ┌───────────────────────────┐              ┌───────────────────────────┐
        │ 服务 IGameService          │              │ EventBus<TEvent>          │
        │ （不继承 MonoBehaviour）    │─────────────▶│ 发布方不认识监听者         │
        │ Time/UI/Input/Audio/…      │              │ 广播中订阅退订安全         │
        └───────────────────────────┘              └───────────────────────────┘
                     │
                     ▼ 一个模块 = 一个 asmdef = 一个命名空间（依赖单向、不可传递）
```

**八条铁律**（完整版在 `CLAUDE.md`）：

1. **服务不继承 MonoBehaviour** —— 实现 `IGameService`，由 `Bootstrap` 统一驱动
2. **模块间只通过事件与接口通信** —— 一个模块 = 一个 asmdef + 一个命名空间
3. **数值与文本进配置表**，代码零魔法数字
4. **禁用 `Resources.Load`**（资源走 `AssetService`）；异步统一走 **UniTask**
5. **禁止直接 `Debug.Log`** —— 一律走日志门面 `Log.*`
6. **第三方插件只读**（`Assets/Plugins/UniTask`、`_ThirdParty`）
7. **重逻辑模块必须同步带 EditMode 测试**
8. **拆卸路径必须"有序且必然终止"** —— 违反的表现是退出 Play 时编辑器静默卡死

**为什么这么设计**：顺序即语义（注册顺序 = 依赖顺序，`Init` 时全部服务已就绪）；可摘除性（可选模块删掉不影响底座）；可回灌（模板会被 clone 成多份，底座只读、靠 `git merge` + 测试吃更新）。

## 五、底座代码要不要全读

**不用全读。** 分三层：

### 第一层 · 必读（约 950 行，一个下午）

这些是**规则**，业务代码写得对不对全靠它们：

| 文件 | 行数 | 读完你会知道 |
|---|---|---|
| `CLAUDE.md` 的「已知的坑」 | — | **先读这个**，10 分钟省几小时 |
| `Core/Services/IGameService.cs` | 32 | 服务契约（Init / Tick / Dispose） |
| `Core/Services/ServiceLocator.cs` | 131 | 怎么取服务、什么时候不能取 |
| `Core/App/Bootstrap.cs` | 206 | 注册 / Init / Tick / Dispose 的**顺序**（顺序就是语义） |
| `Core/Eventing/EventBus.cs` | 275 | 事件是 struct、广播快照语义、**必须退订** |
| `Core/Timing/TimeService.cs` | 239 | 双时钟（Scaled / Unscaled）、冻结 |
| `UI/UiPanel.cs` | 67 | 面板生命周期钩子 |

### 第二层 · 用之前读接口，不读实现

每个服务只看两样：**类头的大段中文注释**（写了"为什么这么设计 + 怎么用"）、**public 方法列表**：

```bash
grep -n "public " Assets/_Project/Scripts/Audio/AudioService.cs     # 20 行看完一个模块的 API 面
```

要写音频功能了，花 15 分钟读 `AudioService` 的注释和 API；没写到就跳过。**要现成例子就直接抄 [常用API示例.md](常用API示例.md)。**

### 第三层 · 不用读，出问题再翻

`UIService` 内部的栈管理、`Config/Editor` 导入管线、`GameLogHandler`、`Extensions`、`Configs/Generated`（自动生成的，勿手改）—— 这些是实现细节，坏了有测试兜着。

### 最快的学法：把 Demo 当教学脚本读

`DemoRunner.cs` 不是功能代码，它是**"每个模块怎么用"的串讲**，顺序与 Console 日志一一对应：

1. Play 一次，对着 Console 看它演了什么
2. 打开 `DemoRunner.cs`，找到打出那行日志的代码
3. 你会发现"播放 3D 音效就是一行 `_audio.PlaySoundAt(clip, pos)`"

写自己的系统时，照它的样子写。

## 六、写你的第一个系统

### 1）先判断形态：**它有没有"位置"？**

| 什么样的东西 | 写成什么 |
|---|---|
| 全局唯一、跨场景活着、没有位置概念（分数、进度、背包数据、关卡状态） | **服务**：实现 `IGameService`，用"登记—装配"两段式注册 |
| 场景里的具体东西（玩家、敌人、宝箱、触发器、UI 面板） | **普通 MonoBehaviour**，挂场景或预制体上 |

> "服务不继承 MonoBehaviour"这条铁律管的是**前者**，不是让你什么都写成服务。判断口诀：**它有没有"位置"** —— 有位置的必然是场景物体。

### 2）服务起手式

```csharp
// _Project/Scripts/Gameplay/Inventory/InventoryService.cs（或你自己的 Assets/Scripts/Game/ 下）
using Template.Core.App;
using Template.Core.Services;

namespace Jam
{
    public sealed class InventoryService : IGameService
    {
        public void Init() { }        // 启动阶段一次：初始化、解析依赖
        public void Dispose() { }     // 拆卸路径必须有序且必然终止（铁律 8）
    }

    // 登记—装配两段式（与其它模块同款）：此处登记，Bootstrap.Awake 统一实例化
    internal static class InventoryServiceBootstrap
    {
        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterAssembliesLoaded)]
        private static void Register() => Bootstrap.AddModuleService(() => new InventoryService());
    }
}
```
需要每帧推进就再加 `ITickable`（实现 `Tick()`），不需要就别加。

### 3）场景物体起手式

```csharp
using UnityEngine;

namespace Jam
{
    public sealed class Chest : MonoBehaviour
    {
        private void Start()          // 用 Start 不用 Awake：服务在 BeforeSceneLoad 就绪，Start 才是"一切都就绪"的档位
        {
            G.Info("Chest", "宝箱就绪");                 // 或 ServiceLocator.Get<InventoryService>()
        }
    }
}
```

> 三种调用底座的方式任选：`G.Audio.PlaySound(clip)`（短入口，推荐）/ `ServiceLocator.Get<AudioService>()` / `ServiceLocator.TryGet(...)`（可选依赖，缺席不炸）。
> `G` 只是把所有 `using Template.*` 收在 `Assets/Scripts/Game/G.cs` 里，让你自己的脚本**只写 `using UnityEngine;`**；具体类型（`UiPanel`、`ItemConfig`…）仍需要各自的 using。

### 4）写一段"验收时间线"（照 DemoRunner 抄）

每做一个系统就写一段"自动演一遍 + 打日志"，Play 一次就能验证：

```csharp
[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]
private static void Run()
{
    if (SceneManager.GetActiveScene().name.StartsWith("InitTestScene")) return;  // 别干扰 PlayMode 测试

    var inv = ServiceLocator.Get<InventoryService>();
    inv.Add("sword", 3);
    Log.Info("Tester", "① 加 3 把剑 → 当前 {0} 把", inv.Count("sword"));
    ServiceLocator.Get<TimeService>().Delay(1f, () => Log.Info("Tester", "② 1 秒后卖掉 1 把 → 剩 {0} 把", inv.Count("sword")));
}
```

要点：**每步都打日志、每步都写清"预期是什么"**。加日志的成本极低，省下的是反复 Play 猜问题的时间。

### 5）测试起手式

```csharp
// _Project/Tests/EditMode/InventoryTests.cs（放进这个目录即属于现成的测试程序集，不用动 asmdef）
using NUnit.Framework;
using Jam;

namespace Template.Tests
{
    public class InventoryTests
    {
        [Test]
        public void Add_IncreasesCount()
        {
            var inv = new InventoryService();
            inv.Add("sword", 3);
            Assert.AreEqual(3, inv.Count("sword"));
        }
    }
}
```

两个坑：① **故意触发 Error 日志的用例，必须在日志出现前 `LogAssert.Expect(...)` 声明**，否则测试失败；② `EventBus` / `ServiceLocator` 是静态的，用例之间要退订清理（见 `Tests/EditMode/EventSubscriptions.cs`）。

## 八、已知的坑（省你几小时）

| 现象 | 原因 / 怎么办 |
|---|---|
| 中文配置/字符串变乱码 | **CSV 与 `.cs` 都必须存 UTF-8**。中文 Windows 的 Excel/编辑器常默认 ANSI(GBK)，存下去就坏了；导入工具只能拒绝非法字节 + 剥 BOM，救不了 GBK |
| `Configs.X.Get(id)` 返回 null | ① 表没导入（改完 CSV 看 Console 有没有 `配置资产已写入`）；② **运行期没人装配配置库** —— 场景里挂 `ConfigInstaller` 并把 `Data/Configs/Generated/ConfigDatabase.asset` 拖进去 |
| `LoadAsync<组件类型>(addr)` 抛 `InvalidKeyException` | Addressables 的带类型接口只认**资产主类型**（prefab 就是 `GameObject`）→ 用 `LoadAsync<GameObject>` 再 `GetComponent<T>()` |
| 面板 `Close` 关不掉 | `UIService.Open(prefab)` 是**克隆**：栈里是克隆体，`Close` 要传 **`Open` 的返回值** |
| 存档"成功"但文件没写 | `SaveService.Save` 目前**恒返回 true**，写盘失败只记 Error → 要确认就自查 `TryGetSlotInfo(slot, out _)` |
| 服务里拿不到 `Camera.main` / 场景物体 | 服务的 `Init` 跑在 **BeforeSceneLoad**（场景还没加载）→ 依赖场景对象的东西一律**懒解析**（首次使用时再找） |
| 退出 Play 时编辑器静默卡死 | 拆卸路径没终止：`while` 每轮必须让集合缩小；先停播、解绑引用再销毁 —— 铁律 8 |
| 重进 Play 出现"幽灵回调" | `EventBus` 是**静态**的：订阅了就必须在 `OnDisable/OnDestroy/Dispose` 退订 |
| 编辑器里 MonoBehaviour 报 "because it is an editor script" | **仅编辑器**程序集里的 MonoBehaviour，文件名**不能**与类名相同 |
| 场景里有两个 EventSystem，你的那套不生效 | 输入层在 `BeforeSceneLoad` 就建了自己的（那时场景还没加载，看不到你的）→ 别在场景里再摆一个 |
| 测试莫名失败 | 见 §6 的两个坑 |

按这个顺序排查，别一上来就翻代码：

4. **Play 中按 F1** —— 看谁在涨：对象池活跃数、事件监听者数、资源账本、GC 次数
5. **各服务的 `Dump()`** —— `AssetService.Dump()` / `VfxService.Dump()` / `PoolService.Dump()` 一行打出全部状态

## 十、从模板开出自己的游戏（五步）

**1. clone 副本，别拷贝目录**（拷贝的话以后模板的修复没法合并回来）

```bash
cd /d/Projects
git clone https://github.com/oreiaboeidenrwmbogis-ship-it/Unity-Game-Framework.git my-game && cd my-game
git tag baseline-4.11          # 记下基线：日后对比与回灌都靠它
```

**2. 加第二个 remote，用于回灌**

```bash
git remote add template https://github.com/oreiaboeidenrwmbogis-ship-it/Unity-Game-Framework.git
# 以后模板更新了：
git fetch template && git merge template/main     # 也可以 git cherry-pick <某个提交> 只挑一阶段
# 合并前/后都跑一遍 Test Runner，绿了才继续
```

**3. 配好环境前提**：`Active Input Handling = Both`（clone 后要手动设一次，编辑器会重启）；要用示例资产就走一次菜单 `Tools/资源/初始化 Addressables 演示分组`。

**4. 目录约定**
- **底座只读**：`Core / UI / Input / Audio / Settings / Config / Save / Assets` —— 要改就先在模板仓库改，再回灌
- 你的东西放 `_Project/Scripts/Gameplay/<系统>/` 或 `Assets/Scripts/Game/<系统>/`，**每个系统一个目录 +（可选）一个 asmdef**
- 类型相关的系统（背包/任务/对话/成就）都做成**可整体删除**的可选模块

**5. 第一次 Play 自检**：直接 Play，Console 应完整演完演示时间线、无红字。这是"底座没问题"的基线，之后再动代码就有对比。
